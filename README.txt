1) CERTIFICATE MOVED TO PROFILE (the actual ask)
---------------------------------------------------
Files: pages/profile/index.html, script.js (+.min.js), style.css (+.min.css)

Profile already had CSS for a ".certificate-grid"/".certificate-card" -
styled, dark, red-accented, with a seal icon - but no HTML ever used it, so
nothing rendered. Built the actual card on top of that existing design
instead of inventing a new one:

  - Locked state (default): dimmed/grayscale card, "Complete Episode 0 and
    Episode 1 to unlock your certificate."
  - Earned state: full color, "Earned", a "View Certificate" button appears
    beneath the card.

"View Certificate" opens the same printable certificate modal as the
Modules page (name, "has successfully completed Episode 0 and Episode 1",
date, "Print / Save as PDF" button via the browser's own print dialog - no
external library). Still no score anywhere, as instructed originally.

The certificate-earned check itself (hasEarnedCertificate) got moved into
services/shared.js so Profile, Modules, and the nav badge below all read
the exact same two flags instead of three separate copies that could drift.


2) NOTIFICATION ON PROFILE
------------------------------
Files: services/shared.js (+.min.js), pages/modules/style.css,
       pages/ep1/style.css, pages/user/style.css, pages/profile/style.css
       (+ all four .min.css)

A small red dot now appears on the "Profile" link in the header nav, on
every page that has one, the moment a student earns the certificate. It's
driven by one new field on the user doc: user.certificateSeen.

  - Earned + not yet seen  -> dot shows
  - Opens the Profile page -> certificateSeen is set true immediately,
    saved, dot disappears everywhere (next page load / next nav render)

This runs through the shared setupNav() (services/shared.js), which every
page already calls - so one change there lights up the dot anywhere that
function runs. The one page where the ORDER mattered was Profile itself:
it used to call setupNav() before fetching fresh data, which would have
decided "should I clear the dot?" from a possibly-stale local cache -
reordered so setupNav() there runs after the fresh Firebase fetch.

WHY ONLY 4 STYLESHEETS, NOT EVERY PAGE
------------------------------------------
Every page builds its header/nav CSS independently (no shared base.css in
this project), so the little red-dot rule technically needs copying into
each one to render. I added it to the pages a student actually lands on
after finishing an episode - Modules, Episode 1, the Home/Dashboard (user),
and Profile itself. I deliberately left out admin-only and pre-login pages
(admin, class, login, signup, etc.) since a notification about a student's
own certificate doesn't mean anything there. Happy to add it to the rest if
you want the dot to be fully universal regardless of page.

NOT CHANGED
--------------
No Firestore rules changes needed - certificateSeen is just a new field on
a student's own user doc, and the existing update rule already lets a
signed-in student edit their own doc as long as they're not changing their
role, so this falls under that.
